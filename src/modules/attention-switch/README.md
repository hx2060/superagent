## 1. 需求理解

### 1.1 需求方描述的问题（2026-11-09 补充）

1. 日程空白时，明明有很多事和工作要做，却不知道做什么；存在对工作的逃避心理，导致无意义消磨。
2. 更具体：某项任务推进到瓶颈，短暂放空后不想再进入；想切换任务，但「切换成什么」不知道，且**思考本身带来负担**；最终滑向短视频，注意力进一步滑落。

### 1.2 需求方想要的（原话要点）

1. 一个「**蓄水池**」：保存所拥有的**所有**有效内容，形成足够的选项储备——不是挑选接受哪几个，而是池子给出足够选项。
2. 保存的目的：进行有效学习、提升自我，或将事件解决。
3. 插件在空白 / 瓶颈期间，能让我找到一个**可以转移注意力的去处**。
4. 功能方向参考过 GTD，但不确定是否合适；**倾向先做最小想法池，验证「整理」是否有用**。

### 1.3 需求明细（需求方给定）

| 维度 | 需求方回答 |
| --- | --- |
| 内容来源 | B站网课、论文、网页学习等；**网课最多** |
| 收录范围 | **都收**——学习内容、工作任务、日常杂事都进池 |
| 使用情境 | 瓶颈 / 空白时刻在**电脑前** |
| 空隙时长 | 基本 30 分钟以上，具体看状态 |
| 频率 | 一天一到两次 |
| 取用形式 | **单独组件**，点击进入对应界面 |
| 选项数量 | 给**几个**（不是只给一个） |
| 核心机制 | **三档学习状态**：按不同学习状态给出不同标准的选项 |

**三档学习状态**（需求方自己定义的核心需求）：

| 档位 | 含义 | 例子 |
| --- | --- | --- |
| 娱乐性学习 | 个人爱好性学习，低门槛、有趣 | 乐理等 |
| 简单看过 | 方便后续进入状态的轻内容 | 轻松浏览即可的内容 |
| 理解学习 | 状态还行，能跟上进度 | 跟网课学习 |

### 1.4 设计解读（待需求方确认）

- 「思考本身带来负担」→ 取用流程必须**零思考**：进入界面 → 选当前状态 → 直接给选项；不要求用户自己琢磨「该干嘛」。
- 「不是挑选接受哪几个，而是池子给足够选项」→ 收录端**零门槛**（都收），筛选由三档状态完成。
- 「先做最小想法池验证整理是否有用」→ 第一版目标是**验证假设**，不是完整 GTD。GTD 的「捕捉 / 整理」约等于收录 + 三档；「执行」由用户点开链接自行完成，暂不引入 next-action / review 等机制。
- 关键区分不变：**当前状态只有需求方本人能感知**，因此三档选择必须是手动的一步点击，不能自动推断。

## 2. 项目现状查询（模块分离形式下的积木）

以下为对当前仓库的实际查询结果（当前 `main`，接口版本 `0.6`，已含 PR #9 的当日计划 / 收集区 / 逾期回顾 / 全天任务）：

**已落地模块与注册点**（`src/app.js` 中每个模块 = 1 处 import + 1 个槽位 + 1 处 mount / destroy + `index.html` 中 1 行样式 link）：

| 模块 | 槽位 | 共享服务 | 数据快照 |
| --- | --- | --- | --- |
| `daily-tasks` | 日视图 `<div data-module-root="daily-tasks">` | `services.dailyTasks` | `data.dailyTasks` |
| `inbox` | 日视图 `<aside class="day-sidebar" data-module-root="inbox">` | `services.inbox` | `data.notes` / `data.tasks` |
| `week-chart` | 周视图 `<div class="mod-week-chart-root" data-module-root="week-chart">` | `services.inbox` | `data.events` / `data.tasks` |

**可用的数据与服务**：

- `Task`：`{ id, title, icon, status, date?, start?, duration?, end?, due? }`。无日期无截止 = **收集区**（未排期）；填 `date` 绑定该日并同步日 / 周 / 月；`date` 不带 `start` / `duration` 即**全天任务**（进当日计划与周 / 月，不进时间表）；`due` 不得早于 `date`。
- `DailyTask`：`{ id, title, icon?, recurrence: 'daily' }`；状态按日隔离。
- `src/tasks.js` 共享纯函数：`taskWindow` / `taskDayEntry` / `taskReviewGroups` / `taskMonthAnchors`——「任务占据哪些天、算什么状态」的唯一口径，月 / 周 / 日三视图共用；新模块应复用，不得另写一套日期逻辑。
- `services.inbox` / `services.dailyTasks`：增改删、三态循环、订阅；`inbox` 另提供 `listUnscheduledTasks()`（收集区）。
- `window.schedule`：dsh 运行时输入接口（`docs/schedule-api.md`）。

**扩展点规则**（`AGENTS.md` 第 2 节、`docs/interfaces.md` 5.1）：新模块放 `src/modules/<name>/`，遵守 `mount(context)` 契约；样式 `.mod-<name>-` 前缀；新 service 键必须可选、先提案；主干注册改动需评审。

**持久化边界**：编辑只存当前页面会话；具体内容写 `local/schedule.json`（不提交）；仓库只交机制层。

**结论**：蓄水池是**新实体**，与 `Task` / `DailyTask` 并列，而非改造它们；可以完全按模块分离落地。主干改动上限：一个视图槽位 + 一个可选 service 键 + 一行样式 `<link>`（最小版不需要新 service）。数据侧新增本地内容与 `src/data.js` 的可选读取，均为增量。

## 3. 模块概念（蓄水池）

- **实体**：`PoolItem`（池条目）——所拥有内容的索引：标题、链接、来源、档位、备注。
- **收录**：零门槛，都收；三种输入形式（模块内表单 / dsh 下发 / 本地文件）都接入。
- **取用**：点击进入蓄水池界面 → 选三档之一 → 给出几个该档选项 → 点击打开链接。
- **与清单的联动（单向）**：清单任务可以放入蓄水池；蓄水池内容不要求回到清单——池子里可以放可选、偏娱乐、不必要但有意义的内容。
- 界面标题建议直接用需求方的词「**蓄水池**」，模块名 `attention-switch` 不变。

```ts
// 草案，正式契约见第 8 节
interface PoolItem {
  id: string;
  title: string;                        // 纯文本
  url?: string;                         // B站 / 论文 / 网页链接
  source: 'course' | 'paper' | 'web' | 'work' | 'chore';  // 来源；网课最多
  tiers: Array<'leisure' | 'browse' | 'deep'>;            // 三档归属；多档（待确认）
  note?: string;                        // 备注：为什么想学 / 要做什么
  createdAt: string;                    // YYYY-MM-DD
}
```

## 4. 候选执行方案

以下均为提案，未选定，按「从小到大」排列；方案之间可组合。

### 方案一：最小蓄水池（验证「整理」是否有用）

- **形式**：日视图一个模块槽位，点击进入蓄水池界面：三档选择 + 每档给出几个选项 + 点击打开链接；收录用模块内手工表单（标题 / 链接 / 来源 / 档位）。
- **需求映射**：直接对应「蓄水池 + 三档 + 几个选项 + 单独组件」的最小集合，即需求方要的「最小想法池」。
- **模块与接入点**：`src/modules/attention-switch/{index.js, README.md, styles.css, __tests__/}`；主干新增日视图槽位一行 + 样式 link 一行；**不需要新 service**。
- **数据 / 接口变更**：新增 `PoolItem` 实体与本地内容（`local/pool.json` 或 `local/schedule.json` 的 `pool` 键，不提交仓库）；`src/data.js` 增加可选读取；同步 `docs/interfaces.md`。
- **验证**：store 纯逻辑（校验 / 分档 / 选取）node:test；UI 按 1440 / 1024 / 768 / 390 本地验证，证据留 `local/evidence/`。
- **优点**：最小可用、可回退；收录与取用都零思考。
- **代价**：收录靠手工；无记录，无法事后判断效果（见方案二）。

### 方案二：最小蓄水池 + 轻记录

- **形式**：方案一 + 记录每次「取用」（时刻、档位、选了哪个条目），会话内或本地轻量留存。
- **需求映射**：回答「整理是否有用」——用取用频次 / 档位分布作最朴素的验证信号。
- **数据 / 接口变更**：本地记录（不提交）；无新发布字段。
- **优点**：假设可验证；仍零自动推断。
- **代价**：记录字段与留存时长是新产品决策（开放问题 6）。

### 方案三：蓄水池 + 与既有清单的联动

- **形式**：方案二 + 工作任务 / 日常杂事入池二选一：a. 只作手工收录的池条目；b. 读取 `services.inbox`，把清单任务也作为候选选项呈现。
- **需求映射**：收录范围「都收」的完整落地。
- **优点**：池与日程一体化，少一处录入。
- **代价**：b 引入模块间只读依赖与口径问题（任务状态 / 当日计划语义）；建议第一版用 a，验证后再考虑 b。

### 方案四（对照，不建议）：直接按 GTD 全套搭建

- **形式**：capture / clarify / organize / review / next-action 全机制。
- **代价**：违背「先做最小想法池验证」的明确倾向；复杂度前置，假设未验证。
- **列出目的**：确认边界——第一版只做「捕捉 + 整理 + 给选项」。

### 7.2 两个疑问的解释

**Q1 档位归属：一个条目打一档，还是可以属多档？**

- 场景：一门网课，状态好时当「理解学习」跟；想轻松点时也可以当「简单看过」翻一翻。如果每条只能打一档，同一个链接要存两遍，池子很快就重复、变乱。
- 选项 A（建议）：**一条目可属多档**——收录时档位用多选（勾选）；界面按所选状态列出所有含该档的条目。
- 选项 B（从简）：**一条目一档**——收录时单选；数据最简，但跨状态的条目要录两遍。
- 建议 A：收录时多勾一下，换来池子不重复。若你更看重录入最简，选 B 也可以，后续再升级。

**Q6 取用记录：模块要不要悄悄记下每次「选了哪档、点了哪个条目」？**

- 用途：回答你最初的目标——「验证整理是否有用」。用一段时间后可以看：池子被用了几次、哪档最常被选、哪些条目从没被点过，再决定池子怎么改。
- 选项：(a) 不记（最简，靠感觉判断）；(b) 只记当前页面会话（刷新即忘）；(c) 记到本地文件（刷新后仍在，只存本地、不提交）。
- 建议：**首版不记**（先验证「给选项」本身有没有用）；如果想留数据，第二版按 (c) 做——记「时间 + 档位 + 条目」，只写本地。

### 7.3 首版具体范围（第一迭代 = 方案一 + 上述已定项）

**做什么：**

- 新模块 `src/modules/attention-switch/`：store（纯逻辑）+ UI + 样式 + node:test，遵守 `mount(context)` 契约。
- 主干按既有模式做最小登记（均需评审）：**入口位置待确认（见第 9 节）**——默认为日视图一个槽位 `<div data-module-root="attention-switch"></div>`（改动最小，需先处于日视图进池）；若要求任何视图一键进池，则改为工具栏登记（改动略增）。其余：`index.html` 一行样式 `<link>`；`src/app.js` 创建 store 并作为可选键传入 `services.pool`（沿用 `daily-tasks` 先例）；`window.schedule.pool` 作为 dsh 运行时接口；`src/data.js` 增加本地池内容的可选读取。
- 界面：日视图出现「蓄水池」入口 → 点击进入蓄水池界面（模块 root 内切换，不新增视图）：
  - 三档切换：娱乐性学习 / 简单看过 / 理解学习；
  - 每档呈现几个选项（暂定 5 个；排序暂定「会话内未取用过优先，同级按加入时间倒序」，预留后续调整空间）；
  - 点击选项：有链接的新标签页打开；无链接的展开详情。
- 收录（三种形式全做）：
  1. 模块内表单：标题 / 来源（网课 · 论文 · 网页 · 工作 · 杂事）/ 档位 / 备注；
  2. dsh 下发：`window.schedule.pool.add({ … })`（贴给机器人即入池）；
  3. 本地文件：`local/schedule.json` 的 `pool` 键（不提交），页面启动时读取，缺失 / 损坏回退空池。
- 联动（单向）：蓄水池界面内「从清单加入」——只读 `services.inbox` 列出清单任务，点某一任务即入池（来源默认「工作」，档位自选）；池 → 清单方向不做。
- 数据：`PoolItem`（见第 8 节）；会话内可增删，刷新回到本地文件初值（与现有模块一致）。

**明确不做（留待后续）：** 取用记录（Q6，第二版再议）、档位自动推荐、GTD 其他机制、池 → 清单同步、工具栏级常驻入口（首版入口在日视图；若体验上需要「任何视图一键进池」，再评估工具栏登记）。

## 8. 最小接口提案（草案，待评审）

```ts
// 数据契约（增量）
interface PoolItem {
  id: string;                  // 集合内唯一
  title: string;               // 纯文本，1–80 字符
  url?: string;                // http(s) 链接；省略时条目只有详情
  source: 'course' | 'paper' | 'web' | 'work' | 'chore';   // 来源；网课最多
  tiers: Array<'leisure' | 'browse' | 'deep'>;             // 非空；多档（待 Q1 确认）
  note?: string;               // 纯文本，最多 200 字符
  createdAt: string;           // YYYY-MM-DD
}
```

- **本地内容**：`local/schedule.json` 增加可选 `pool` 键（`PoolItem[]`）；缺失 / 损坏回退空池；不提交仓库。
- **service（可选键）**：`services.pool`——`addItem / updateItem / deleteItem / listItems / listByTier(tier) / optionsFor(tier, count?) / markUsed(id) / subscribe(listener)`；同步方法非法输入抛带 `code` 的 `Error`；返回值是数据副本；`markUsed` 只写会话内标记（供排序），不产生历史。
- **dsh 接口**：`window.schedule.pool.add({ id?, title, url?, source, tiers, note? })` / `.list()` / `.remove(id)`；字段与校验同 service；随实现更新 `docs/schedule-api.md`。
- **DOM 契约**：`[data-module-root="attention-switch"]`、`[data-attention-switch-tier]`、`[data-attention-switch-option="<id>"]`、`[data-attention-switch-add-toggle]`、`[data-attention-switch-form]`、`[data-attention-switch-input]`、`[data-attention-switch-live]`。
- **错误码**：`POOL_TITLE_INVALID` / `POOL_SOURCE_INVALID` / `POOL_TIER_INVALID` / `POOL_URL_INVALID` / `POOL_DUPLICATE_ID` / `POOL_NOT_FOUND`。
